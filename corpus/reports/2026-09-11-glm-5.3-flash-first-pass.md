# First full eval pass on GLM 5.3 Flash — 2026-09-11/12

**Purpose.** Run every eval entry point once with *every* agent — Extractor,
Matcher, Steward, Curator, Tagger, Contribution Reviewer, Dispute Arbitrator —
and the scorecard judge on the cheap tier (`z-ai/glm-5.3-flash` via
OpenRouter), to learn roughly what a full pass costs in tokens and wall-clock,
get preliminary numbers, and find the problems in the evals themselves before
spending on the production models. Nothing here is a quality baseline: the
judge is the same model as the agents (`--allow-same-model-judge`), Steward
runs were capped, and the sandbox blocked the Steward's source fetches
(§ Caveats).

Branch: `claude/loving-allen-9sy8sy`. Every problem below that says *fixed*
has a commit on that branch; the cluster runs themselves ran on the code as
of each launch, so several ran *before* the fix that their failure prompted.

What that buys: 268 top-level claims across the four clusters, **13 assessments**
(eggs 6, lableak 3, blackholes 4, lethalities 0), and 235 claims left pending
stewardship at the caps (eggs 15, lableak 41, blackholes 16, lethalities 163).

**Per unit, on GLM through OpenRouter:**

- An extraction call: 10–30k input, 1–60k output (reasoning), 1–15 min.
- A Matcher decision: 3–7 turns, ~1–2 min, ≈ $0.002–0.004. It is the
  most-called agent (455 calls on lethalities) because every top-level claim
  and every subclaim passes through it.
- A Steward run: 3–10 turns, **20–30 min**, ≈ $0.03–0.05 including the
  Matcher calls it makes. Latency, not tokens, is the binding cost: a single
  call takes 30–200 s because GLM writes 1–16k tokens of reasoning per turn.
- The judge: ≈ $0.003 per claim.

**Extrapolation to an uncapped drain.** 235 pending Steward runs at ≈ $0.04
and ≈ 25 min each is ≈ $10 and ≈ 100 sequential hours, before the subclaims
those runs mint (each Steward run on eggs minted ~2 new claims, each a new
Steward run). Tokens are not the constraint on this model; wall-clock is,
unless the drain is parallelized.

## Problems found in the evals (and what was done)

The theme: **GLM 5.3 Flash does not honour tool schemas or output budgets the
way the Claude adapters assume**, and the harness had several silent paths
where a missing field or a cut-off turn became a quiet no-op. Most of these
would bite any non-Anthropic model; several bite the production Matcher pin
today.

1. **Steward could not run on a non-Anthropic model at all.** `web_search` is
   an Anthropic server tool; the OpenRouter adapter refuses it. *Fixed*:
   gated on provider (as mandate-review already did), with a briefing note.
2. **A corpus run assesses nothing by default.** Stewardship is funded work; a
   reset corpus DB has no General mandate and the fallback lane is opt-in, so
   every claim sat pending with no warning (first smoke: 7 claims, 0 Steward
   runs, 0 diagnostics). *Fixed*: `corpus:run` warns up front and reports the
   pending count; README documents `BACKGROUND_FALLBACK_LANE_ENABLED`.
3. **`STEWARD_MAX_RUNS` was per post, not per run** (drain cap applied to each
   post's drain). *Fixed* in `run.ts`; README wording is now true.
4. **Extractor truncation.** GLM's reasoning exhausted the hard-coded 16384
   output tokens on most posts → 0 claims for the source (eggs posts 2 and 3;
   every first attempt on lableak/blackholes/lethalities). *Fixed*: new
   `EXTRACTION_MAX_TOKENS`; the runs used 65536.
5. **OpenRouter upstream errors** arrive as HTTP 200 + `finish_reason:
   "error"`; the adapter reported "model did not return the forced tool call"
   and the source failed. *Fixed*: retried, billed, and classified transient.
6. **Matcher decisions missing required fields.** GLM returned decisions whose
   reasoning named the matched claim at 0.9+ confidence but carried neither
   `is_match` nor `matched_claim_id`; read as-is, `undefined` is falsy → a
   duplicate node. 4 of 7 golden failures as shipped. *Fixed*: the tool
   refuses and asks for a resubmit.
7. **`API_KEYS` in the environment 401s every submit** (the runner relies on
   the dev auth bypass). Documented.
8. **Latency.** 30–200 s per call; a Steward run is 20–30 min. Not fixable
   here; it is what a full run costs on this tier.
9. **Prose instead of a tool call.** After a refused submission GLM said
   "resubmitting…" and ended its turn → no decision (all 5 failures of golden
   run 2). *Fixed*: opt-in `finalToolNudge` in `toolUseLoop`; Matcher uses it.
10. **Matcher `maxTokens` 4096** cut GLM's in-content reasoning mid-thought on
    a third of golden pairs; a `max_tokens` turn ended the loop with no
    decision. *Fixed*: 16384.
11. **Invalid-JSON tool arguments** threw and killed the whole agent run
    (golden run 4 died at 14/14; lethalities post 7 lost). *Fixed*: the call is
    answered with the parse message and the model tries again.
12. **`update_claim_assessment` stored the literal `"undefined"`** when GLM
    omitted `status` (3 of 6 eggs assessments; the reasoning argued
    "supported"). *Fixed*: bounced with the enum.
13. **Judge verdicts arrive incomplete**: one with every field missing (NaN
    means in the scorecard), one without `flags` (crash after the whole scored
    run was paid for). *Fixed*: tolerate missing flags; retry an empty verdict
    once, then skip it.
14. **Steward records cited URLs as `sources` rows** (eggs: 15 sources for 3
    posts, 12 with no instances). Not a bug per se, but the report's
    per-source table reads oddly. Not changed.
15. **A content-less source row pre-empts a later submission**: blackholes post
    2 hit the row the Steward had made for its URL, the worker fetched arxiv,
    got 403, post lost. *Fixed* in `getOrCreateSource`.
16. **The dominant failure: turns cut at `max_tokens` end the run silently.**
    The final step was a `max_tokens` cutoff for **28 of 34 Steward runs**
    (6/6 lethalities, 5/8 lableak, 17/20 blackholes; cap 16384) and **141 of
    293 Matcher runs**. `toolUseLoop` treated `max_tokens` as a graceful stop
    (a server-tool safety) and every such run ended with nothing recorded:
    lethalities finished with 169 claims and zero assessments. *Fixed*: the
    loop resumes (twice max) when no server tool is in the toolset.
    *Verified* on a one-post eggs run on the finished branch (3 Steward runs,
    `runs/eggs-2026-09-12T03-02-42-520Z`): 3 of 3 Steward runs recorded an
    assessment (contested 0.85, contested 0.70, supported 0.85; traces
    ~3k chars), 3 `max_tokens` recoveries and 5 refused-and-resubmitted tool
    calls fired along the way, one judge verdict was retried; $0.24, 68 min,
    16 / 16 / 9 min per Steward run.
17. **Contribution reviewer ends without a decision** (2 of 10) → claimed and
    pending until the reclaim window. *Fixed*: conditional final-tool nudge.
18. **The reviewer on GLM never flags bad faith**, even on the spam and the
    cover-up challenge the scenario wrote for it. Worth a look at the prompt
    or the model before reading the bad-faith rate as a property of the org.
19. **Judge review sheet (`corpus:calibrate review`) was not run**: with 3–6
    judged claims per cluster there is not enough to review, and the judge is
    the agent's own model. Do it on the production-model pass.
20. **`predictions`** was not seeded: it is a longitudinal track and a
    disposable corpus DB gives it nothing.

## Caveats

- **Egress.** This sandbox's proxy blocks wikipedia, arxiv, substack and the
  rest; every `provenance_read_source` call failed with 403 (18 in lableak, 17
  in blackholes). The Steward assessed from memory and said so, which is why
  nearly every judged assessment carries `hallucination_risk`. On a machine
  with open egress the picture may differ a lot.
- **No web_search on GLM** (Anthropic-only), independent of the above.
- **Same-model judge**, small samples, capped runs: read the judged numbers as
  smoke, not signal.
- **Order of fixes.** eggs ran before problems 4–16 were fixed; lableak,
  blackholes and lethalities before 6–16; the golden run 5 and the small
  verification run are the only runs on the finished branch.
